# U61 — Initialiser PostgreSQL et lancer des scripts une seule fois

[← Index des cas d’usage](./index.md)

Dans un projet en `version: 2`, un fichier SQL texte peut initialiser un
**nouveau** volume PostgreSQL :

```yaml
services:
  postgres:
    version: "18"
    initialization:
      sql: database/initial.sql
      once: {id: grants-v1, script: scripts/postgres-once.sh}
```

`database/initial.sql` peut créer des rôles et une base, ou contenir un dump
SQL texte. Un dump au format personnalisé n'est pas accepté. Créer le fichier
avant `make validate`. Ne jamais placer de mot de passe en clair dans un
fichier versionné ; `.env` reste le support des valeurs locales.

Pour une application `linked` ou `managed`, ajouter sous son bloc :

```yaml
initialization:
  once: {id: setup-v1, script: scripts/setup.sh}
```

Le script applicatif est relatif au répertoire de l'application ; le script
du service est relatif à la racine du projet. Ils s'exécutent avec `sh` dans
leurs conteneurs après les healthchecks, au premier `make up` ou
`make update` applicable. `make init` n'exécute rien dans Docker.

Vérifier avec `make doctor`. Un second `make update` ne rejoue pas les scripts.
Changer l'`id` demande explicitement une nouvelle exécution ; changer seulement
le contenu du script ne suffit pas. En cas d'échec, inspecter les éventuels
effets partiels avant de relancer. Un volume PostgreSQL déjà initialisé ne
rejoue jamais `initial.sql` ; Yia signale alors un marqueur absent ou une
empreinte différente sans supprimer la base.
