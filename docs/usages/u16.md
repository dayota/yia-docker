# U16 — Exposer une application Nuxt avec Node 24 et pnpm

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Configuration de référence Node

Réutiliser `package.json` et `server.mjs` de U24, ou les véritables sources
Nuxt, dans `apps/frontend`. Le script `dev` est obligatoire. Le fichier Yia est :

```yaml
version: 1
project:
  name: node-frontend
environment:
  domain: node-frontend.localhost
applications:
  frontend:
    type: node
    path: apps/frontend
    runtime:
      node: "24"
      package_manager: pnpm
    framework:
      name: nuxt
      version: 4
    web:
      hostname: node-frontend.localhost
      port: 3000
```

```bash
make init
make validate
make update
curl --fail --resolve node-frontend.localhost:80:127.0.0.1 \
  http://node-frontend.localhost/
make exec SERVICE=frontend CMD="node --version"
make exec SERVICE=frontend CMD="pnpm --version"
make doctor FORMAT=json
```

Yia crée `apache` et `node-24-frontend`. Le port 3000 reste privé ; Apache est
le seul point d'entrée sur l'hôte. Le processus reçoit `--host 0.0.0.0` et
`--port 3000`, et le proxy relaie Upgrade/WebSocket pour le HMR Nuxt. Le volume
`node-frontend-modules` isole `node_modules`. Deux passages supplémentaires de
`make update` doivent préserver service, source et volume. Voir [T02](./t02.md) si
le hostname ou le port 80 ne répond pas.
