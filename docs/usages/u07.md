# U07 — Valider et inspecter la configuration

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Parcours valide

Sur U06 ou U24, exécuter :

```bash
make validate
make validate FORMAT=json
make config
```

`validate` contrôle le schéma, les chemins applicatifs, le `package.json` et son
script `dev` pour Node, ainsi que les variables obligatoires comme
`POSTGRES_PASSWORD`. Sa sortie JSON est déterministe et son code de sortie vaut
zéro lorsque le projet est valide. `config` affiche ensuite le modèle normalisé :
chemins résolus, applications ordonnées et valeurs par défaut telles que
`package_manager: pnpm` ou `postgres.expose: false`. Aucune valeur issue de
`.env` n'est affichée.

Pour observer une erreur structurée, ajouter temporairement une propriété
inconnue, par exemple `http_port: 8080` sous `environment`, puis lancer :

```bash
make validate FORMAT=json
```

La commande doit échouer avec le code stable `YIA_CONFIG_INVALID`, un message
humain et le chemin de validation dans le contexte structuré. Retirer la
propriété, relancer `make validate`, puis seulement `make generate` ou
`make update`. Ne jamais poursuivre à partir d'une configuration que Yia a
refusée. Le parcours de diagnostic détaillé se trouve dans [T03](./t03.md).
