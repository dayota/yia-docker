# U32 — Gérer `.env` et `.env.example`

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

`.env.example` documente les clés et des valeurs non sensibles ; `.env`
contient les valeurs locales et doit être ignoré par Git. `make init` crée le
second depuis le premier uniquement s'il est absent, puis ne l'écrase jamais.

```bash
git check-ignore .env
make validate FORMAT=json
make config
```

Ni `validate`, ni `config`, ni les artefacts sous `.yia-runtime/` et
`.agents/` ne doivent contenir `POSTGRES_PASSWORD`. Les valeurs
`POSTGRES_USER` et `POSTGRES_DB` n'initialisent qu'un volume vide ; les changer
ne migre pas une base existante.
