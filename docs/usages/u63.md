# U63 — Démarrer Redis persistant

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

Ce scénario nécessite Docker, Compose et un projet contenant le sous-module
Yia `.yia/`, installé comme dans [U03](./u03.md). Aucune application n'est
nécessaire. Redis peut aussi être ajouté à un projet V2 avec PostgreSQL.

Arborescence initiale :

```text
redis-demo/
├── .git/
├── .gitmodules
├── .yia/
├── .gitignore
├── Makefile
├── yia.yml
├── .env.example
└── .env
```

Le Makefile est le proxy fourni par Yia. `.gitignore` exclut `.env`,
`.yia-runtime/` et `.yia-data/`. Aucun fichier applicatif n'est nécessaire.

`yia.yml` complet :

```yaml
version: 2
project:
  name: redis-demo
environment:
  domain: redis-demo.localhost
services:
  redis:
    enabled: true
    version: "7.4"
    expose: false
applications: {}
```

`.env.example` contient uniquement la clé attendue :

```dotenv
REDIS_PASSWORD=
```

Créer `.env` depuis cet exemple et renseigner un mot de passe local non vide.
Ne pas versionner `.env`. Puis exécuter :

```bash
make init
make validate FORMAT=json
make update
make update
make status FORMAT=json
make doctor FORMAT=json
make logs SERVICE=redis
```

Seul Redis démarre, avec un healthcheck sain, sans Apache et sans port hôte.
Le second `update` indique que les fichiers sont déjà à jour et ne recrée pas
le conteneur. La documentation générée décrit `redis-data`, le réseau et la
variable attendue sans copier son secret.

Vérifier le refus d'une connexion non authentifiée :

```bash
make exec SERVICE=redis CMD="redis-cli PING"
```

La réponse doit signaler `NOAUTH`. Pour vérifier les commandes authentifiées,
ouvrir un shell dans Redis et utiliser sa variable locale :

```bash
make shell SERVICE=redis
export REDISCLI_AUTH="$REDIS_PASSWORD"
redis-cli PING
redis-cli SET yia:demo preserved
exit
```

`PING` retourne `PONG` et `SET` retourne `OK`. Ensuite :

```bash
make down
make update
make shell SERVICE=redis
export REDISCLI_AUTH="$REDIS_PASSWORD"
redis-cli GET yia:demo
exit
```

`GET` retourne `preserved`. Le volume `redis-demo_redis-data` conserve les
données AOF et RDB ; les commandes ordinaires ne le suppriment pas. Le journal
AOF est synchronisé chaque seconde : une panne brutale peut perdre environ
une seconde d'écritures.

Les applications du réseau privé se connectent à `redis:6379` avec le mot de
passe local et leur propre bibliothèque cliente. Pour un outil sur l'hôte,
remplacer `expose: false` par `expose: true`, puis :

```bash
make validate
make update
make doctor
```

L'accès devient disponible uniquement sur `127.0.0.1:6379`, avec le même mot
de passe. Un port occupé provoque une erreur ; Yia ne choisit pas un autre port.

Pour arrêter et retirer l'environnement tout en conservant les données :

```bash
make destroy
```

La suppression définitive des données utilise uniquement `make destroy-data`
et sa confirmation explicite. Voir [U33](./u33.md). Retirer Redis de
`yia.yml` puis exécuter `make update` retire son conteneur et conserve son volume.
