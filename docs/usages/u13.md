# U13 — Activer Xdebug pour une seule application

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Diff de configuration

Dans U11, activer Xdebug uniquement pour `api` :

```diff
     runtime:
       php: "8.4"
+      xdebug: true
```

Conserver `runtime.xdebug: false`, ou omettre la propriété, pour `backoffice`.
Exécuter `make update`, puis configurer l'IDE pour écouter sur le port 9003 avec
le mapping de chemin `/workspace/api` vers `apps/api`. Déclencher explicitement
une requête :

```bash
curl --fail --resolve api.php-shared.localhost:80:127.0.0.1 \
  'http://api.php-shared.localhost/?XDEBUG_TRIGGER=1'
```

Xdebug cible `host.docker.internal:9003`; Compose fournit l'alias Linux
nécessaire. Aucune session ne démarre sans trigger et `backoffice` reste
désactivé, bien que les deux pools partagent `php-8.4`. Le port 9003 appartient
à l'IDE sur l'hôte et n'est pas publié par le container.
