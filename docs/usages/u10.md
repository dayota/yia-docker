# U10 — Exécuter un worker ou une commande PHP sans HTTP

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Omettre volontairement `web`

Une application PHP peut exister sans hostname ni Apache :

```yaml
version: 1
project:
  name: php-worker
environment:
  domain: php-worker.localhost
applications:
  worker:
    type: php
    path: apps/worker
    runtime:
      php: "8.4"
    framework:
      name: laravel
      version: 13
```

Après `make init` et `make update`, seul `php-8.4` est attendu. Le champ
`environment.domain` reste obligatoire en V1, même si aucune URL n'est exposée.
Exécuter une commande ponctuelle ou ouvrir un shell dans le répertoire de
l'application :

```bash
make exec SERVICE=worker CMD="php --version"
make shell SERVICE=worker
```

Dans un vrai Laravel, `make exec SERVICE=worker CMD="php artisan queue:work --once"`
permet un traitement ponctuel. Yia ne transforme pas automatiquement cette
commande en service long-lived : la topologie V1 démarre PHP-FPM et laisse la
supervision métier hors de ce contrat.
