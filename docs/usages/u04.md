# U04 — Initialiser un projet consommateur

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Entrées et commande

Préparer au minimum `.yia/`, `Makefile` et un `yia.yml` valide. Ajouter aussi
`.env.example` avant l'initialisation pour documenter les variables du projet ;
si `.env` existe déjà, Yia doit le préserver octet pour octet.

```bash
make init
```

`init` valide toutes les entrées avant d'écrire, crée les fichiers projet
manquants seulement, installe la documentation et les deux skills projet, puis
génère `.yia-runtime/`. Il ne contacte pas le daemon Docker et ne démarre aucun
container. Le résumé indique les fichiers créés et préservés, les applications,
les runtimes, les services et les URLs.

Contrôler immédiatement le résultat :

```bash
make validate
make config
git status --short
```

Les fichiers humains attendus incluent `AGENTS.md`, `.agents/docs/INDEX.md`, le
glossaire et les répertoires de décisions, ainsi que les skills `project-docs`
et `update-project-docs`. Les fichiers sous `.agents/` appartiennent désormais
au projet ; `.yia-runtime/` reste reconstructible. Une seconde commande
`make init` sur un projet complètement initialisé est refusée et oriente vers
`make update`, ce qui évite une réinitialisation silencieuse.
