# U11 — Héberger plusieurs applications sur le même PHP

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Mutualiser le runtime, isoler les applications

Le fichier complet reprend deux applications sur le même runtime :

```yaml
version: 1
project:
  name: php-shared
environment:
  domain: php-shared.localhost
applications:
  api:
    type: php
    path: apps/api
    runtime:
      php: "8.4"
    framework:
      name: laravel
    web:
      hostname: api.php-shared.localhost
      public_directory: public
  backoffice:
    type: php
    path: apps/backoffice
    runtime:
      php: "8.4"
    framework:
      name: symfony
    web:
      hostname: backoffice.php-shared.localhost
      public_directory: public
```

Après `make update`, les services sont `apache` et un unique `php-8.4`. Chaque
application possède toutefois son pool FPM, sa source montée sous
`/workspace/<application>` et son volume `php-<application>-vendor`.

```bash
curl --fail --resolve api.php-shared.localhost:80:127.0.0.1 \
  http://api.php-shared.localhost/
curl --fail --resolve backoffice.php-shared.localhost:80:127.0.0.1 \
  http://backoffice.php-shared.localhost/
make exec SERVICE=api CMD="composer install --no-interaction"
make exec SERVICE=backoffice CMD="composer install --no-interaction"
```

Une dépendance installée dans une application ne doit pas apparaître dans le
volume de l'autre. Deux `make update` supplémentaires ne recréent ni le runtime
partagé ni les volumes.
