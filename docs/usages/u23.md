# U23 — Associer une API PHP et un frontend Nuxt

[← Index des cas d’usage](./index.md) · [Gestion du guide](../usages-management.md)

## Objectif

Reprendre le routage HTTP de [U24](./u24.md) pour une architecture sans base de
données : une API PHP 8.4 sur `api.php-node.localhost` et un frontend Node 24
sur `php-node.localhost`. Apache reste le seul service publié sur l'hôte.

Cette variante convient notamment lorsque la base est distante ou lorsque le
projet n'en a pas besoin. Yia ne déduit pas une dépendance PostgreSQL depuis le
framework déclaré.

## Partir de U24

Conserver le `Makefile`, `.gitignore`, `apps/api/public/index.php`,
`apps/frontend/package.json` et `apps/frontend/server.mjs` de U24. Remplacer
`yia.yml` par la configuration complète suivante :

```yaml
version: 1
project:
  name: php-node
environment:
  domain: php-node.localhost
applications:
  api:
    type: php
    path: apps/api
    runtime:
      php: "8.4"
    framework:
      name: laravel
      version: 13
    web:
      hostname: api.php-node.localhost
      public_directory: public
  frontend:
    type: node
    path: apps/frontend
    runtime:
      node: "24"
    framework:
      name: nuxt
      version: 4
    web:
      hostname: php-node.localhost
      port: 3000
```

Supprimer les variables `POSTGRES_*` de `.env.example`. Un fichier `.env` vide
reste valide et peut être créé par `make init` s'il n'existe pas. Il demeure un
fichier local ignoré par Git.

## Initialiser et vérifier

```bash
make init
make validate
make update
curl --fail --resolve api.php-node.localhost:80:127.0.0.1 \
  http://api.php-node.localhost/
curl --fail --resolve php-node.localhost:80:127.0.0.1 \
  http://php-node.localhost/
make ps FORMAT=json
make doctor FORMAT=json
```

Les deux réponses sont celles de U24. Les seuls services attendus sont :

```text
apache
node-24-frontend
php-8.4
```

La sortie de `ps` ne doit contenir aucun service ni volume PostgreSQL. Une
seconde exécution de `make update` ne doit recréer aucun container. Utiliser
ensuite `make down` ou `make destroy` selon que l'on souhaite conserver ou
supprimer l'environnement ; les volumes de dépendances restent préservés dans
les deux cas. En cas d'échec de routage, consulter [T02](./t02.md) ; si le runtime
généré paraît incomplet, consulter [T05](./t05.md).
